# 当前后端已实现功能说明

## 1. 文档目的

本文档说明当前 `backend` 仓库已经落地的后端能力，供开发、测试和前端联调用作统一参考。

## 2. 总体结论

当前后端已覆盖在线考试系统的核心业务能力，并在以下方面完成增强：

- JWT + Spring Security 登录鉴权
- 管理员、教师、学生三类账号与权限控制
- 题库聚合、试卷管理、自动组卷
- 考试冻结、共享快照、考试撤销
- 学生考试会话流、直接交卷、成绩统计
- 留言与回复

从“业务能力是否具备”的角度看，当前仓库已经可以支撑：

- JWT 登录、刷新、登出、当前用户恢复
- 管理员、教师、学生信息管理
- 三类题目维护：选择题、填空题、判断题
- 试卷题目管理与按科目练习
- 自动组卷
- 考试管理
- 在线考试开考、暂存答案、交卷
- 成绩查询与成绩统计
- 留言与回复
- 全局题库聚合分页与题库删除

## 3. 基础约定

### 3.1 统一返回结构

绝大多数接口都返回统一结构：

```json
{
  "code": 200,
  "message": "请求成功",
  "data": {}
}
```

说明：

- `code = 200` 表示成功
- 业务异常通常返回 `400`、`401`、`403`、`404`、`410` 等
- `data` 的具体结构由各接口决定

### 3.2 登录态与角色

当前登录态已改为 JWT：

- `POST /auth/login`
- `POST /auth/refresh`
- `POST /auth/logout`
- `GET /auth/me`

前端需在请求头中携带：

```txt
Authorization: Bearer <accessToken>
```

角色约定：

- `ADMIN`
- `TEACHER`
- `STUDENT`

### 3.3 密码存储

账号密码已切换为 `BCrypt` 存储：

- 新增账号时自动加密
- 修改账号资料时若包含密码字段会按 BCrypt 落库
- 学生改密、管理员重置密码会按 BCrypt 落库

旧明文密码数据需要先执行迁移后，才能使用新的 `/auth/login`。

### 3.4 时间约定

考试相关时间主要使用上海时区：`Asia/Shanghai`。

`ExamManage.examStartAt` 推荐前端使用 ISO-8601 传入，例如：

```txt
2026-04-22T09:00:00
```

后端同时兼容 `examDate` 的字符串形式，例如：

```txt
yyyy-MM-dd HH:mm:ss
```

## 4. 已实现功能清单

### 4.1 认证与会话

已实现：

- 登录 `POST /auth/login`
- 刷新令牌 `POST /auth/refresh`
- 登出 `POST /auth/logout`
- 获取当前用户 `GET /auth/me`
- Access Token + Refresh Token 双令牌机制
- Refresh Token 持久化到 `auth_refresh_token` 表
- 基于 Spring Security 的统一认证、鉴权、401/403 JSON 返回

### 4.2 权限控制

已实现默认权限矩阵：

- `ADMIN`：管理员、教师、学生账号管理；考试撤销
- `ADMIN` / `TEACHER`：题库、试卷、考试、成绩总览与统计、冻结试卷查看
- `STUDENT`：学生考试会话、直接交卷、本人资料、本人改密、本人成绩

额外约束：

- 学生不能直接查看完整试卷 `GET /paper/{paperId}`
- 学生不能直接查看冻结快照试卷 `GET /exam/{examCode}/frozen-paper`
- 学生访问个人资料和成绩接口时，只允许访问本人数据
- `POST /answer/submit` 中的 `studentId` 以后端当前登录学生为准

### 4.3 管理员管理

已实现：

- 查询全部管理员
- 按 ID 查询管理员
- 新增管理员
- 修改管理员
- 删除管理员
- 重置管理员密码

### 4.4 教师管理

已实现：

- 教师分页查询
- 按多条件过滤：教师编号、姓名、学院、职称/类型、电话、邮箱
- 按 ID 查询教师
- 新增教师
- 修改教师
- 删除教师

### 4.5 学生管理

已实现：

- 学生分页查询
- 按多条件过滤：学号、姓名、年级、电话、学院、专业、班级
- 按 ID 查询学生
- 新增学生
- 修改学生
- 修改学生密码
- 删除学生

### 4.6 题目管理

已实现三类题目的维护能力：

- 选择题新增、编辑、查询最新题号
- 填空题新增、编辑、查询最新题号
- 判断题新增、编辑、查询最新题号

题型编号约定：

- `1`: 选择题
- `2`: 填空题
- `3`: 判断题

### 4.7 全局题库聚合

已实现：

- 全局题库聚合分页接口 `GET /question-bank/{page}/{size}`
- 按题型过滤
- 按科目过滤
- 按关键字搜索题干

实现方式：

- 底层通过 `UNION ALL` 聚合 `multi_question`、`fill_question`、`judge_question`
- 返回统一的 `QuestionBankItemVO` 结构

### 4.8 题库删除

已实现：

- 删除题库题目 `DELETE /question-bank/{questionType}/{questionId}`

删除规则：

- 先检查题目是否存在
- 再检查该题是否被试卷引用
- 如果引用它的试卷已经进入冻结窗口，或考试已撤销，则拒绝删除
- 如果允许删除，先删除 `paper_manage` 中的关联，再删除对应题目表中的题目记录

### 4.9 试卷管理

已实现：

- 查询全部试卷题目关联 `GET /papers`
- 根据试卷 ID 获取试卷完整题目 `GET /paper/{paperId}`
- 根据科目获取练习题库 `GET /practice/{source}`
- 手动向试卷中加入题目 `POST /paperManage`
- 删除试卷中的某一道题 `GET /paper/delete/{paperId}/{type}/{questionId}`
- 清空整张试卷的题目关联 `DELETE /paper/deleteAll/{paperId}`
- 获取试卷总分 `GET /paper/score/{paperId}`

额外规则：

- 试卷总分当前按每题固定 2 分计算
- 如果试卷已关联到进入冻结窗口的考试，则不允许继续调整题目结构

### 4.10 自动组卷

已实现：

- 自动组卷接口 `POST /item`

能力说明：

- 先按 `paperId` 清空旧题目关联
- 再根据科目、选择题数量、填空题数量、判断题数量批量抽题入卷
- 如果某一题型数量不足，会直接返回失败

### 4.11 考试管理

已实现：

- 查询全部考试
- 考试分页查询
- 按考试编号查询考试
- 新增考试
- 修改考试
- 删除考试
- 获取最后一条考试记录/最近试卷信息 `GET /examManagePaperId`
- 查询考试策略 `GET /exam/{examCode}/exam-policy`

考试策略接口返回：

- `examCode`
- `examStartAt`
- `freezeAt`
- `paperLocked`
- `revoked`
- `snapshotReady`
- `windowEndAt`
- `inExamWindow`
- `serverTime`

### 4.12 冻结、快照与撤销

已实现：

- 冻结时刻 = 开考前 1 小时
- 进入冻结窗口后，试卷结构锁定
- 冻结试卷快照接口 `GET /exam/{examCode}/frozen-paper`
- 管理员撤销考试 `POST /admin/exam/{examCode}/revoke`
- 撤销后写入审计信息

### 4.13 学生在线考试流程

已实现完整学生考试会话流：

- 开始或恢复考试 `POST /student/exam/{examCode}/attempt/start`
- 暂存答案 `PUT /student/exam/{examCode}/attempt/answers`
- 正式交卷 `POST /student/exam/{examCode}/attempt/submit`

流程能力：

- 自动校验学生是否属于本场考试范围
- 自动校验当前时间是否在考试开放窗口内
- 开始考试时返回脱敏后的试卷内容，隐藏标准答案与解析
- 允许重复进入未提交的考试并恢复答案
- 暂存答案时按 `questionType_questionId` 键保存
- 交卷时按冻结后的试卷快照判分

### 4.14 直接交卷接口

已实现：

- 直接交卷接口 `POST /answer/submit`

说明：

- 该接口接收 `AnswerVO`
- 会计算得分并写入 `score` 表
- 当前只允许学生角色访问
- 学生身份以后端上下文为准，不再信任客户端传入的 `studentId`

### 4.15 成绩管理

已实现：

- 查询全部成绩 `GET /scores`
- 分页查询某学生成绩 `GET /score/{page}/{size}/{studentId}`
- 查询某学生全部成绩 `GET /score/{studentId}`
- 新增成绩 `POST /score`
- 查询某场考试全部成绩 `GET /scores/{examCode}`
- 成绩统计接口 `GET /score/statistics/{examCode}`

### 4.16 消息交流

已实现：

- 留言分页查询 `GET /messages/{page}/{size}`
- 留言详情 `GET /message/{id}`
- 新增留言 `POST /message`
- 删除留言 `DELETE /message/{id}`
- 新增回复 `POST /replay`
- 按留言查询回复列表 `GET /replay/{messageId}`

## 6. 前端对接建议

建议前端按以下优先级对接：

1. 登录后保存 `accessToken`、`refreshToken`、`user`
2. 所有受保护请求统一携带 `Authorization: Bearer <accessToken>`
3. `401` 时优先走 `/auth/refresh` 自动续期
4. 正式考试流程优先走学生考试会话接口
5. 教师端/管理员端查看正式考试题目时优先走冻结快照接口
6. 题库删除、试卷编辑、考试编辑前，处理后端关于“冻结/撤销”的业务拒绝提示
