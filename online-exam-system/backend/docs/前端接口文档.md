# 前端接口文档

本文档基于当前 `backend` 仓库代码整理，适用于 JWT + Spring Security 改造后的联调版本。

## 1. 基本信息

### 1.1 基础地址

```txt
http://localhost:8080
```

### 1.2 统一返回格式

```json
{
  "code": 200,
  "message": "请求成功",
  "data": {}
}
```

字段说明：

- `code`: 业务状态码，`200` 表示成功
- `message`: 提示信息
- `data`: 业务数据

### 1.3 认证方式

当前项目已从 Cookie 登录态切换为 JWT：

- 前端登录成功后保存 `accessToken`、`refreshToken`、`user`
- 业务请求统一携带请求头 `Authorization: Bearer <accessToken>`
- 不再使用 `rb_token`、`rb_role` Cookie

角色值：

- `ADMIN`
- `TEACHER`
- `STUDENT`

### 1.4 路径占位规则

学生和教师的分页筛选接口使用路径参数，不支持直接缺省。对于“不筛选”的字段，请传 `@`。

示例：

```txt
GET /students/1/10/@/@/@/@/@/@/@
GET /teachers/1/10/@/@/@/@/@/@
```

### 1.5 题型编号

- `1`: 选择题
- `2`: 填空题
- `3`: 判断题

## 2. 推荐对接顺序

1. 登录 `POST /auth/login`
2. 页面初始化时调用 `GET /auth/me`
3. 管理端对接用户、题库、试卷、考试、成绩接口
4. 学生考试页对接考试会话流：
   - `POST /student/exam/{examCode}/attempt/start`
   - `PUT /student/exam/{examCode}/attempt/answers`
   - `POST /student/exam/{examCode}/attempt/submit`
5. `401` 时调用 `POST /auth/refresh` 刷新令牌并重放请求

## 3. 认证接口

### 3.1 登录

- 方法: `POST`
- 路径: `/auth/login`

请求体：

```json
{
  "username": "10001",
  "password": "123456",
  "role": "ADMIN"
}
```

说明：

- `username` 为账号编号，统一按字符串传输
- `role` 必填，可选值为 `ADMIN`、`TEACHER`、`STUDENT`

成功响应示例：

```json
{
  "code": 200,
  "message": "请求成功",
  "data": {
    "accessToken": "jwt-access-token",
    "refreshToken": "jwt-refresh-token",
    "tokenType": "Bearer",
    "expiresIn": 900,
    "user": {
      "userId": 10001,
      "username": "10001",
      "displayName": "张三",
      "role": "STUDENT"
    }
  }
}
```

### 3.2 刷新令牌

- 方法: `POST`
- 路径: `/auth/refresh`

请求体：

```json
{
  "refreshToken": "jwt-refresh-token"
}
```

返回结构与登录成功时一致。

### 3.3 退出登录

- 方法: `POST`
- 路径: `/auth/logout`

请求体：

```json
{
  "refreshToken": "jwt-refresh-token"
}
```

说明：

- 后端会废弃该 refresh token
- 前端无论后端是否成功，都应清空本地登录态

### 3.4 获取当前登录用户

- 方法: `GET`
- 路径: `/auth/me`
- 请求头: `Authorization: Bearer <accessToken>`

响应示例：

```json
{
  "code": 200,
  "message": "请求成功",
  "data": {
    "userId": 10001,
    "username": "10001",
    "displayName": "张三",
    "role": "STUDENT"
  }
}
```

## 4. 权限约定

- `ADMIN`: 管理员、教师、学生账号管理；考试撤销
- `ADMIN` / `TEACHER`: 题库、试卷、考试管理；冻结试卷查看；成绩总览与统计
- `STUDENT`: 学生考试会话、直接交卷；本人资料、本人成绩、本人改密

关键限制：

- 学生不能访问 `GET /paper/{paperId}`
- 学生不能访问 `GET /exam/{examCode}/frozen-paper`
- 学生访问 `/student/{studentId}`、`/score/{studentId}`、`/score/{page}/{size}/{studentId}` 时，只允许访问本人数据
- `POST /answer/submit` 中的 `studentId` 以后端当前登录学生为准，前端不应自行伪造

### 5.7 学生考试会话接口

#### 开始或恢复考试

- 方法: `POST`
- 路径: `/student/exam/{examCode}/attempt/start`

返回字段：

- `attemptId`
- `serverTime`
- `windowEndAt`
- `paper`
- `answers`

#### 暂存答案

- 方法: `PUT`
- 路径: `/student/exam/{examCode}/attempt/answers`

请求示例：

```json
{
  "answers": {
    "1_10001": "A",
    "2_20003": "TCP",
    "3_30002": "T"
  }
}
```

#### 正式交卷

- 方法: `POST`
- 路径: `/student/exam/{examCode}/attempt/submit`

返回字段：

- `etScore`
- `maxScore`
- `passed`
- `correctCount`
- `totalQuestions`

### 5.8 直接交卷接口

- 方法: `POST`
- 路径: `/answer/submit`

请求示例：

```json
{
  "examCode": 1001,
  "studentId": 20230001,
  "answers": [
    {
      "questionType": 1,
      "questionId": 10001,
      "answer": "A"
    }
  ]
}
```

说明：

- `studentId` 字段会由后端按当前登录学生覆盖
- 正式考试页优先使用考试会话流，不建议只依赖该接口

## 7. 对接注意事项

- 所有受保护接口都需要 `Authorization` 头
- 前端不再使用 `withCredentials` 传 Cookie
- access token 失效时，应使用 refresh token 自动刷新
- refresh token 失效后，应跳回登录页
- 数据库需要先执行 [auth_security_upgrade.sql](/D:/test/online-exam-system/backend/sql/auth_security_upgrade.sql)
- 现有账号密码需要先迁移为 BCrypt 后，才能用新的 `/auth/login`
