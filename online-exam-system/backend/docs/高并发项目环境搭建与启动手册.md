# 高并发项目环境搭建与启动手册

## 1. 文档用途

这份文档用于让组员在一台全新的 Windows 开发机上，把当前 `online-exam-system` 高并发版本从零搭起来，并成功跑通：

- 单实例开发启动
- 双实例 + `Nginx` 统一入口启动
- `Memurai` 缓存
- `RabbitMQ` 异步系统
- `MySQL` 主从读写分离
- `Prometheus` 监控抓取
- `k6` 压测

本文按 `2026-04-20` 仓库状态编写。

## 2. 先看整体链路

当前推荐的完整本地拓扑如下：

```text
Browser
  -> http://localhost:8080        Nginx 入口
  -> http://localhost:8081        前端开发服务器（仅开发，不走 Nginx）

Nginx 8080
  -> Backend A 18080
  -> Backend B 18081

Backend
  -> MySQL Primary 3306
  -> MySQL Replica 3307
  -> Memurai 6379
  -> RabbitMQ 5672 / 15672 / 15692
  -> Prometheus 9090
```

如果你只想快速开发而不是完整验证高并发链路，最常用的是：

- 前端：`http://localhost:8081`
- 后端：`http://localhost:18080`
- 前端开发代理：`8081 -> /api -> 18080`

如果你要验证完整入口层、高并发链路和双实例行为，必须使用：

- 浏览器访问 `http://localhost:8080`
- 后端双实例 `18080 + 18081`
- `Nginx + RabbitMQ + Memurai + MySQL Replica + Prometheus` 全部启动

## 3. 强约束和最重要的坑

先看这几条，否则大概率会在第一小时卡住。

### 3.1 当前已支持路径无关化

当前仓库已经做了“路径无关化”处理：

- 仓库根路径由脚本自动按 `$PSScriptRoot` 反推，不再要求必须放在 `D:\test\online-exam-system`
- 外部工具路径优先读取环境变量
- 也支持用本地覆盖文件统一管理，不需要修改正式脚本

本地覆盖文件位置：

- 示例文件：`backend/ops/local/tool-paths.example.ps1`
- 本地文件：`backend/ops/local/tool-paths.local.ps1`

推荐做法：

1. 复制 `tool-paths.example.ps1` 为 `tool-paths.local.ps1`
2. 按自己机器的实际路径修改变量
3. 后续直接运行仓库脚本，不再改正式脚本

当前支持的常用变量：

- `OES_MAVEN_CMD`
- `OES_TOOLS_ROOT`
- `OES_MYSQL_HOME`
- `OES_NGINX_HOME`
- `OES_PROMETHEUS_HOME`
- `OES_K6_HOME`
- `OES_MEMURAI_HOME`
- `OES_RABBITMQ_HOME`
- `OES_ERLANG_HOME`

## 6.1 克隆仓库到固定路径

推荐直接放到：

```powershell
D:\test\online-exam-system
```

如果你的外部工具安装路径和本文默认值不同，先做下面这一步即可。

然后编辑：


```powershell
$env:OES_MAVEN_CMD = "C:\Tools\apache-maven-3.9.15\bin\mvn.cmd"
```

### 6.1.2 在当前终端加载本地工具变量

如果你后面要手工执行 `mysql.exe`、`memurai.exe`、`rabbitmqctl.bat` 这类外部工具命令，建议先在当前 PowerShell 会话加载一次本地变量：


后文凡是出现 `$env:OES_...` 的命令，都默认你已经执行过这一步。

## 6.6 安装 MySQL 主库

推荐口径：

- MySQL `8.4.x`
- 安装到 `D:\MySQL\server`
- root 密码设为 `root`

当前仓库默认配置就是：

```properties
spring.datasource.username=root
spring.datasource.password=root
spring.datasource.url=jdbc:mysql://localhost:3306/online_exam...
```

如果你不想用 `root/root`，可以，但你必须同步修改：

- `backend/src/main/resources/application.properties`
- 或者启动前设置环境变量 `DB_USERNAME`、`DB_PASSWORD`
- 以及 `backend/ops/scripts/setup-mysql-replica.ps1` 里的 `$primaryRootPassword`

### 6.6.1 主库必须打开 binlog

要启用真实从库，主库必须启用二进制日志。

打开你的 MySQL 主库配置文件 `my.ini`，确保至少有下面这些配置：

```ini
[mysqld]
server-id=1
log-bin=mysql-bin
binlog_format=ROW
binlog_row_image=FULL
```

保存后重启 MySQL 服务。

### 6.6.2 创建数据库

```powershell
$mysql = Join-Path $env:OES_MYSQL_HOME "bin\mysql.exe"
& $mysql -uroot -proot -e "CREATE DATABASE IF NOT EXISTS online_exam DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

绝对路径示例：

```powershell
& "D:\MySQL\server\bin\mysql.exe" -uroot -proot -e "CREATE DATABASE IF NOT EXISTS online_exam DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

### 6.6.3 验证主库已具备主从条件

```powershell
$mysql = Join-Path $env:OES_MYSQL_HOME "bin\mysql.exe"
& $mysql -uroot -proot -e "SHOW MASTER STATUS\G"
```

如果这条命令没有返回日志文件和位置，说明你的主库没有正确打开 `binlog`。

## 6.8 搭建 MySQL 从库

### 6.8.1 前提

以下条件必须满足：

- 主库已安装在 `D:\MySQL\server`
- 主库 root 密码是 `root`
- 主库已开启 `binlog`
- 数据库 `online_exam` 已导入完成

### 6.8.2 初始化从库

执行：

```powershell
.\backend\ops\scripts\setup-mysql-replica.ps1
```

这个脚本会：

- 在 `backend/ops/mysql-replica/runtime/` 生成从库配置和运行目录
- 初始化 `3307` 从库实例
- 从 `3306` 导出 `online_exam`
- 配置复制用户 `replica_user`
- 启动复制

### 6.8.3 验证从库

```powershell
$mysql = Join-Path $env:OES_MYSQL_HOME "bin\mysql.exe"
& $mysql --protocol=TCP --host=127.0.0.1 --port=3307 -uroot -e "SHOW REPLICA STATUS\G"
```

你至少要看到：

- `Replica_IO_Running: Yes`
- `Replica_SQL_Running: Yes`
- `Seconds_Behind_Source: 0`

### 6.8.4 安装为 Windows 服务

如果你希望 `3307` 从库以后能长期复用，再执行：

```powershell
.\backend\ops\scripts\install-mysql-replica-service.ps1
```

服务名是：

```text
MySQLReplica3307
```

后续常用命令：

```powershell
Start-Service -Name MySQLReplica3307
sc.exe query MySQLReplica3307
.\backend\ops\scripts\stop-mysql-replica.ps1
```

## 6.9 安装并配置 Memurai

当前项目把 `Memurai` 作为本地 Redis 替代方案使用，默认端口：

```text
127.0.0.1:6379
```

### 6.9.1 推荐做法

推荐把 `memurai.exe` 和 `memurai-cli.exe` 放到：

```text
D:\Memurai
```

### 6.9.2 创建配置文件

创建：

```text
D:\Memurai\memurai.conf
```

写入：

```conf
bind 127.0.0.1
port 6379
appendonly no
save ""
dir D:/test/online-exam-system/backend/target/memurai-data
loglevel notice
logfile D:/test/online-exam-system/backend/target/memurai.log
```

先准备数据目录：

```powershell
New-Item -ItemType Directory -Force -Path ".\backend\target\memurai-data" | Out-Null
```

### 6.9.3 启动 Memurai

如果你用便携版，最简单的启动命令是：

```powershell
$memurai = Join-Path $env:OES_MEMURAI_HOME "memurai.exe"
Start-Process -FilePath $memurai -ArgumentList (Join-Path $env:OES_MEMURAI_HOME "memurai.conf") -WindowStyle Hidden
```

如果你装成了 Windows 服务，也可以直接：

```powershell
Start-Service -Name Memurai
```

### 6.9.4 验证 Memurai

```powershell
$memuraiCli = Join-Path $env:OES_MEMURAI_HOME "memurai-cli.exe"
& $memuraiCli -p 6379 ping
& $memuraiCli -p 6379 info server
```

预期：

- `ping` 返回 `PONG`
- `info server` 能看到 `memurai_version`

### 6.9.5 停止 Memurai

如果你用的是服务：

```powershell
Stop-Service -Name Memurai -Force
```

如果你用的是便携进程：

```powershell
Get-Process memurai -ErrorAction SilentlyContinue | Stop-Process -Force
```

## 6.10 安装并配置 RabbitMQ

当前项目默认 RabbitMQ 连接参数：

```text
host = 127.0.0.1
port = 5672
username = guest
password = guest
vhost = /
```

### 6.10.1 安装路径

推荐路径：

- Erlang：`D:\Erlang OTP`
- RabbitMQ：`D:\RabbitMQ\rabbitmq_server-4.2.5`
- RabbitMQ 运行目录：`D:\RabbitMQ\appdata`

### 6.10.2 创建运行目录

```powershell
New-Item -ItemType Directory -Force -Path "D:\RabbitMQ\appdata" | Out-Null
New-Item -ItemType Directory -Force -Path "D:\RabbitMQ\appdata\log" | Out-Null
New-Item -ItemType Directory -Force -Path "D:\RabbitMQ\appdata\db" | Out-Null
```

### 6.10.3 配置系统环境变量

管理员 PowerShell 执行：

```powershell
[Environment]::SetEnvironmentVariable('ERLANG_HOME', 'D:\Erlang OTP', 'Machine')
[Environment]::SetEnvironmentVariable('RABBITMQ_BASE', 'D:\RabbitMQ\appdata', 'Machine')
[Environment]::SetEnvironmentVariable('RABBITMQ_CONFIG_FILE', 'D:\RabbitMQ\appdata\rabbitmq', 'Machine')
[Environment]::SetEnvironmentVariable('RABBITMQ_ENABLED_PLUGINS_FILE', 'D:\RabbitMQ\appdata\enabled_plugins', 'Machine')
[Environment]::SetEnvironmentVariable('RABBITMQ_LOG_BASE', 'D:\RabbitMQ\appdata\log', 'Machine')
[Environment]::SetEnvironmentVariable('RABBITMQ_MNESIA_BASE', 'D:\RabbitMQ\appdata\db', 'Machine')
```

### 6.10.4 写 RabbitMQ 配置文件

创建：

```text
D:\RabbitMQ\appdata\rabbitmq.conf
```

内容：

```conf
listeners.tcp.default = 5672
management.tcp.ip = 127.0.0.1
management.tcp.port = 15672
prometheus.tcp.ip = 127.0.0.1
prometheus.tcp.port = 15692
loopback_users.guest = true
```

创建：

```text
D:\RabbitMQ\appdata\enabled_plugins
```

内容：

```erlang
[rabbitmq_management,rabbitmq_prometheus].
```

### 6.10.5 修正安装目录下的默认运行根目录

打开：

```text
D:\RabbitMQ\rabbitmq_server-4.2.5\sbin\rabbitmq-defaults.bat
```

确认里面把 `RABBITMQ_BASE` 指向：

```bat
D:\RabbitMQ\appdata
```

这样 RabbitMQ 的数据、日志、配置才会全部落在 `D:`，而不是悄悄回退到 `%APPDATA%\RabbitMQ`。

### 6.10.6 安装或刷新 Windows 服务

管理员 PowerShell 执行：

## 11. 常见问题排查

## 11.1 浏览器访问 8080 不通

按这个顺序查：

1. `frontend/dist` 是否存在
2. `18080` 和 `18081` 是否都已启动
3. `backend-health/18080` 和 `backend-health/18081` 是否可访问
4. 查看 Nginx 日志：
   - `tools/nginx/nginx-1.28.0/logs/online-exam-error.log`
5. 直接前台启动一次 Nginx，看控制台报错

## 11.2 8081 能开，8080 不能开

这通常说明：

- 前端开发服务器正常
- Nginx 没起来，或者配置指向的静态目录/后端不对

请不要把两者混为一谈。

## 11.3 后端脚本一运行就报 Maven 找不到

直接改这两个文件里的 `$maven`：

- `backend/ops/scripts/start-backend-test-instance-18080.ps1`
- `backend/ops/scripts/start-backend-test-instance-18081.ps1`

## 11.4 从库一直起不来

重点检查：

1. 主库是否开启了 `binlog`
2. 主库 root 密码是不是 `root`
3. 主库是否真的是 `D:\MySQL\server`
4. `SHOW MASTER STATUS\G` 是否有输出
5. `SHOW REPLICA STATUS\G` 是否出现：
   - `Replica_IO_Running: Yes`
   - `Replica_SQL_Running: Yes`

## 11.5 RabbitMQ 的 15692 不通

重点检查：

1. `enabled_plugins` 是否写了：
   - `rabbitmq_management`
   - `rabbitmq_prometheus`
2. `rabbitmq.conf` 是否配置了：
   - `prometheus.tcp.port = 15692`
3. `rabbitmq-defaults.bat` 是否指向了 `D:\RabbitMQ\appdata`
4. 服务是否重装或重启过

## 11.6 学生考试中心看不到考试

重点检查：

1. 是否执行过 `2026-04-17_test_exam_setup.sql`
2. 是否又执行过别的旧数据脚本把考试覆盖掉了
3. 是否执行过 `2026-04-17_test_exam_reset.sql`
4. 考试是否还没开始
5. 需要立即进入的话是否执行了 `2026-04-17_test_exam_open_now.sql`

## 11.7 Prometheus targets 有红色 down

先看你是不是只开了单实例。

如果你只开了：

- `18080`

那么 Prometheus 里的：

- `18081 down`

是正常现象。

如果你开了双实例还 down，再去检查：

- 对应实例是否启动
- `actuator/prometheus` 是否可访问
- `prometheus.yml` 中 target 是否正确

## 11.8 Redis/Memurai 没开，后端能不能启动

理论上很多功能可以降级，但不建议把“本地开发能启动”当成“高并发特性已验证”。

如果你的目标是：

- 联调
- 压测
- 高并发功能回归

那就不要省略 `Memurai`。
