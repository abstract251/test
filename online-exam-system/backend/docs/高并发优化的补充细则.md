## Key Changes

- 新文档结构定为“现状分析 + 分阶段路线图 + 配置建议 + 验证方案”，不只给结论，也要把当前代码中的具体瓶颈点写清楚。
- 文档开头先固定当前系统画像：
    - 前端：frontend/src/utils/request.js 里 baseURL 直指 http://localhost:8080，无 /api 网关前缀。
    - 后端：backend/src/main/resources/application.properties 只有单实例端口与 MySQL 连接配置，无 Redis/MQ/网关配置。
    - 运行容器：Spring MVC + Tomcat，不是 WebFlux；数据库连接池是 HikariCP。
    - 持久层：大量 MyBatis 注解 SQL，存在 select *、全表分页、UNION ALL 聚合分页等典型压力点。
- 文档正文必须显式列出当前热点瓶颈，至少包括：
    - 自动组卷三类题型都使用 ORDER BY RAND() LIMIT n，属于典型高并发禁用 SQL。
    - 学生交卷在 StudentExamSessionServiceImpl 中按题逐条 findByQuestionId 判分，存在 N+1 查库。
    - 冻结快照读取在 ExamSnapshotServiceImpl 中按题逐条回表，存在另一条 N+1。
    - 教师考试列表前端使用 Promise.allSettled(getExamPolicy) 做逐场补请求，列表放大后会放大后端压力。
    - 学生答题自动保存仍是高频写路径，需要明确改为缓冲、合并、降频。
    - 生产环境仍开启 mybatis-plus.configuration.log-impl=StdOutImpl，高并发下会放大 IO 开销。
    - paper_manage 原始脚本无主键/唯一约束，score 原始脚本只有主键 scoreId，未围绕热点查询建立完整索引。
    - 刷新令牌 auth_refresh_token 目前完全走 MySQL，不具备缓存减压层。
    - 考试快照生成当前依赖 JVM 内 ConcurrentHashMap 锁，多实例后不成立。
- 文档中“分阶段优化路线图”固定为 8 个阶段，每阶段统一采用以下子结构，保证风格一致且可执行：
    - 阶段目标
    - 当前现状与瓶颈
    - 具体改造动作
    - 涉及组件/代码区域
    - 前置依赖
    - 风险与回滚
    - 验收指标
- 8 个阶段的内容范围固定如下：
    - Phase 0：基线压测、容量模型、可观测性。
    - Phase 1：前端减请求、静态资源减载、答题保存降频。
    - Phase 2：Nginx 入口层、负载均衡、限流、防刷、双实例部署。
    - Phase 3：应用热点链路重构，先做代码级减载。
    - Phase 4：两级缓存体系，Caffeine + Redis。
    - Phase 5：数据库与 SQL 优化、索引补齐、读写分离。
    - Phase 6：RabbitMQ 异步削峰、Outbox/幂等消费。
    - Phase 7：Tomcat、Hikari、JVM、日志与资源调优。
    - Phase 8：压测、灰度、降级与回滚。
- 每个阶段必须写到“可实施”粒度，不能只写口号。例如：
    - Phase 1 要写明教师考试列表去掉逐项 getExamPolicy、前端统一改 /api 相对路径、搜索加 debounce、学生答题保存从 900ms 写库改为 3-5 秒批量 flush。
    - Phase 3 要写明替换 ORDER BY RAND() 的方案、交卷判分改为“快照生成时缓存正确答案映射”、考试快照读取改为按题型批量查询、学生考试列表改为 DB 侧过滤。
    - Phase 4 要写明缓存对象、key 设计、TTL、失效触发点、回源策略。
    - Phase 5 要写明首批索引建议：paper_manage(paperId, questionType, questionId)、score(examCode, studentId)、exam_manage(exam_start_at)、范围字段联合索引等。
    - Phase 6 要写明事件名、同步与异步边界、Outbox 原则、消费幂等。
    - Phase 7 要写明 Tomcat/Hikari 的调优是“后置动作”，不能在前面几阶段未减载时直接堆线程。
- 文档中单独增加“关键配置建议”章节，用表格列出建议新增的配置项与用途，覆盖：
    - Nginx：upstream、静态资源缓存、gzip、限流、keepalive、超时。
    - Spring Boot：Actuator、日志级别、生产 profile。
    - Tomcat：maxThreads、acceptCount、maxConnections。
    - Hikari：maximumPoolSize、连接超时、泄漏检测思路。
    - Redis：热点考试详情、冻结快照、作答草稿、refresh token 热状态、分布式锁。
    - RabbitMQ：队列命名、削峰对象、消费者幂等。
    - MySQL：慢查询日志、主从复制、主从读写分工。
- 文档中单独增加“压测与验收方案”章节，明确：
    - 使用 k6 作为推荐压测工具。
    - 至少覆盖登录、考试列表、开始考试、暂存答案、交卷、题库分页六条压测链路。
    - 验收维度包括 QPS / P95 / P99 / 错误率 / MySQL 连接数 / 慢 SQL / Redis 命中率 / MQ 堆积 / JVM GC。
- 文档结尾增加“当前不建议立即做的事”章节，避免误导实施顺序：
    - 首轮不以微服务拆分为前提。
    - 首轮不做分库分表。
    - 首轮不做 Kafka 级事件平台。
    - 首轮不把判分主链路彻底异步化。
