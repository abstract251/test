# 前端剩余功能执行规划

最后更新：`2026-04-14`

## 1. 文档目的

本文档用于固化当前前端剩余功能的实施顺序、页面范围、接口映射与验收标准，后续开发默认以本文档为执行基线。

本规划基于以下文档与当前前端代码现状整理：

- `backend/docs/前端接口文档.md`
- `backend/docs/当前后端已实现功能说明.md`
- 当前 `frontend/src` 实际代码

## 2. 已确认决策

- 管理员端直接对齐后端完整功能，不再只保留“教师管理”单点能力。
- 撤销考试只在管理员端展示，当前系统内只有一种管理员角色。
- 成绩管理页需要包含图表展示。
- 全局题库管理单独新建页面，不替换现有“题库工作台”。
- 管理员可以查看和管理消息模块。

## 3. 实施原则

- 页面视觉、布局、交互语气保持与现有前端一致，继续沿用现有布局和公共组件。
- 新页面文案遵循 `docs/frontend-copy-guideline.md`，只面向用户说明“能做什么、下一步怎么做”，不展示研发过程、接口名、联调说明。
- 管理员与教师共享的功能优先复用同一套页面和组件，不复制两份同构代码。
- 先补业务闭环，再补增强能力，最后做统一收尾。
- 每个阶段完成后至少执行一次 `npm run build`，关键路径完成后补浏览器联调。

- 教师端已有考试管理、试卷编辑、题库工作台，可作为管理员端复用基础。

## 6. 分阶段执行计划

### 阶段 0：公共基础整理

目标：先补足后续阶段共用的 API、路由和菜单基础，避免后续重复改动。

主要任务：

- 新增 API 模块：
  - `src/api/adminApi.js`
  - `src/api/scoreApi.js`
  - `src/api/messageApi.js`
  - `src/api/questionBankApi.js`
- 扩展路由：
  - 管理员增加管理员管理、学生管理、考试管理、全局题库、成绩管理、消息管理入口
  - 教师增加全局题库、消息管理入口
  - 学生增加消息中心入口
- 扩展菜单常量：
  - 更新 `src/utils/constants.js`
- 预留图表组件基础：
  - 在 `src/components/charts` 下建立成绩分布图表组件
- 统一共享策略：
  - 管理员与教师共用的页面优先复用现有教师页面
  - 如果单页中出现大量角色分支，再抽到共享目录，不直接复制第二份页面

验收标准：

- 菜单与路由结构完整可访问
- 新增 API 文件具备基础方法定义
- 不出现“管理员和教师分别维护两套完全相同页面”的实现方式

### 阶段 1：成绩闭环

目标：先补齐“交卷后可查看结果”的主业务闭环。

主要任务：

- 学生端“我的成绩”页替换占位页
- 教师/管理员端“成绩管理”页替换占位页
- 接入图表展示
- 补充交卷后结果高亮或本场成绩提示

页面范围：

- `学生 / 我的成绩`
- `教师 / 成绩管理`
- `管理员 / 成绩管理`

接口映射：

- `GET /score/{page}/{size}/{studentId}`
- `GET /score/{studentId}`
- `GET /scores/{examCode}`
- `GET /score/statistics/{examCode}`
- `POST /score`
- `GET /scores`

实现要点：

- 学生页展示历史成绩列表，并突出最近一次交卷结果。
- 教师/管理员页采用“考试选择 + 汇总卡片 + 分布图 + 成绩表”的结构。
- 分布图展示分数段人数，至少覆盖 `0-59 / 60-69 / 70-79 / 80-89 / 90-100`。
- 若保留手动录入成绩能力，放在教师/管理员页弹窗中处理。
- 图表只承担展示职责，页面文案仍保持用户导向，不写技术说明。

验收标准：

- 学生交卷后进入真实成绩页，不再落到占位页。
- 教师和管理员都能查看单场考试成绩及统计图表。
- 空数据状态、异常提示、加载状态完整。

### 阶段 2：全局题库管理

目标：新增独立的全局题库管理页，不替换当前“题库工作台”。

主要任务：

- 新建“全局题库管理”页面
- 支持分页、题型筛选、科目筛选、关键字搜索
- 支持删除题目
- 复用现有题目新增/编辑页

页面范围：

- `教师 / 全局题库管理`
- `管理员 / 全局题库管理`

接口映射：

- `GET /question-bank/{page}/{size}`
- `DELETE /question-bank/{questionType}/{questionId}`
- 三类题目的新增与编辑接口

实现要点：

- 当前“题库工作台”继续保留，用于按科目查看和维护题目。
- “全局题库管理”作为独立页面，定位为完整题库总览与统一管理入口。
- 列表页支持进入现有题目编辑页。
- 删除时正确提示“冻结考试关联题不可删除”等业务拒绝信息。
- 分页和筛选条件需要保留，避免用户操作后列表状态丢失。

验收标准：

- 教师和管理员都能从菜单进入全局题库页。
- 分页、筛选、删除、编辑跳转完整可用。
- 页面文案不出现“聚合接口”“后端接口”等技术描述。

### 阶段 3：管理员完整功能补齐

目标：让管理员端从单点教师管理扩展为完整后台。

主要任务：

- 新增管理员管理页面：
  - 管理员列表
  - 新增管理员
  - 编辑管理员
  - 删除管理员
- 管理员复用学生管理页面
- 管理员复用考试管理页面
- 管理员复用试卷编辑页面
- 管理员复用成绩管理页面
- 管理员复用全局题库管理页面
- 管理员复用消息管理页面

接口映射：

- `GET /admins`
- `GET /admin/{adminId}`
- `POST /admin`
- `PUT /admin/{adminId}`
- `DELETE /admin/{adminId}`
- 现有教师、学生、考试、成绩、题库、消息相关接口

实现要点：

- 现有教师端页面如可复用，优先通过路由和权限扩展接入管理员端。
- 仅管理员管理相关页面单独新增。
- 管理员菜单应至少包含：
  - 控制台
  - 管理员管理
  - 教师管理
  - 学生管理
  - 考试管理
  - 全局题库管理
  - 成绩管理
  - 消息管理

验收标准：

- 管理员登录后具备完整后台导航。
- 管理员管理 CRUD 全链路可用。
- 管理员可访问其余业务模块，不需要借道教师端。

### 阶段 4：考试增强能力

目标：把后端已经具备但前端尚未用上的考试增强能力补齐。

主要任务：

- 在试卷编辑页增加自动组卷入口
- 在考试管理页补冻结快照预览
- 在管理员考试管理页补“撤销考试”操作
- 更明确展示冻结、撤销、考试窗口等状态

接口映射：

- `POST /item`
- `GET /exam/{examCode}/exam-policy`
- `GET /exam/{examCode}/frozen-paper`
- `POST /admin/exam/{examCode}/revoke`

实现要点：

- 自动组卷建议用弹窗或抽屉录入科目与题量要求。
- 试卷预览逻辑调整为：
  - 未冻结时优先预览当前试卷
  - 已冻结时优先预览冻结快照
- 撤销考试只在管理员端显示。
- 撤销弹窗必须填写原因。
- 考试列表、详情或编辑页应明确显示“已冻结”“已撤销”等状态。

验收标准：

- 管理员可撤销考试，教师端不可见该动作。
- 已冻结考试可查看固定题面。
- 自动组卷成功后，试卷编辑页和总分展示立即刷新。

### 阶段 5：消息模块

目标：补齐学生、教师、管理员三端消息主链。

主要任务：

- 学生端新增消息中心
- 教师端新增消息管理页
- 管理员端新增消息管理页
- 支持留言列表、详情、回复、删除

页面范围：

- `学生 / 消息中心`
- `教师 / 消息管理`
- `管理员 / 消息管理`

接口映射：

- `GET /messages/{page}/{size}`
- `GET /message/{id}`
- `POST /message`
- `DELETE /message/{id}`
- `POST /replay`
- `GET /replay/{messageId}`

实现要点：

- 学生端以“发起留言 + 查看回复”为主。
- 教师和管理员端以“查看消息 + 回复 + 删除”为主。
- 消息详情页或详情抽屉中展示回复列表。
- 如果联调时发现消息数据缺少发布者身份字段，第一版先按全量列表展示，不做复杂筛选。

验收标准：

- 学生可发消息并查看回复。
- 教师和管理员可查看、回复、删除消息。
- 留言列表、详情、回复链可完整闭环。

### 阶段 6：统一收尾与联调

- 检查管理员/教师/学生三端关键流程
- 补移动端基础适配：
  - 学生成绩页
  - 学生消息中心
  - 在线答题页剩余细节
- 执行构建与必要的手工联调

建议联调清单：

- 登录与退出登录
- 401 失效跳转
- 学生交卷到成绩查看
- 教师查看成绩统计与图表
- 管理员撤销考试
- 管理员管理 CRUD
- 全局题库删除异常提示
- 消息留言与回复闭环

验收标准：

- `npm run build` 通过
- 三端核心页面均可正常访问
- 关键业务链无占位页残留

## 8. 联调观察项

- `GET /admins` 列表返回字段需确认是否包含 `adminId`，若不包含，管理员列表页需补详情拉取或推动后端补字段。
- `Message` 模型当前字段较少，如缺少发布者身份与姓名，第一版消息列表先不做发送者筛选。
- 成绩相关接口存在 `/score/{studentId}` 与 `/score/{page}/{size}/{studentId}` 两种路径，封装 API 时要避免路径混淆。
- 全局题库聚合结果需要确认是否足够支撑直接编辑；若字段缺失，再决定是否补单题详情接口。
