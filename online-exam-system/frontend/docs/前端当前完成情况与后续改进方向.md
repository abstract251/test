## 5. 建议联调顺序

在你启动前后端后，建议按以下顺序做浏览器联调：

1. 登录管理员账号，检查控制台导航、管理员管理、考试管理、成绩管理、消息管理是否都可进入。
2. 登录学生账号，检查考试中心是否按年级/专业/学院正确筛选考试。
3. 从学生端进入考试详情，再进入答题页，验证答题、暂存、交卷、跳成绩页链路。
4. 打开学生成绩页，核对最近成绩卡片、历史列表、分页和移动端样式。
5. 打开教师或管理员成绩管理页，核对考试切换、汇总卡片、分布图、成绩表。
6. 从学生端提交留言，再用教师或管理员账号查看、回复、删除，验证消息闭环。
7. 用管理员账号检查撤销考试、固定题面预览、自动组卷后的刷新反馈。

## 6. 后续改进方向

### 6.1 优先级高

- 完成真实浏览器联调，并记录每条关键链路的结果与异常提示。
- 对消息模块补“仅看我的留言”能力。
  前提是后端消息模型补充发送者身份或用户标识字段。
- 对成绩、消息、考试页面补真实空数据、异常数据、边界时间数据测试。

### 6.2 优先级中

- 清理现有部分页面中的乱码文案与编码历史问题。
  当前在部分旧页面里仍能看到异常字符显示，建议统一按 UTF-8 校正。
- 进一步优化学生答题页。
  可补题号导航、未答题提醒、考试结束后的自动处理策略。
- 进一步优化学生消息中心。
  可补留言创建成功后的更明确反馈，以及更稳定的“我的留言”筛选体验。
- 为教师/管理员消息管理页补移动端专用列表展示。

### 6.3 优先级低

- 进一步压缩前端包体。
  当前 `npm run build` 仍有 vendor 包体积告警，但不影响功能可用。
- 补更细的视觉统一收口。
  例如统一抽屉宽度策略、分页区在不同页面的移动端表现、卡片信息密度等。
