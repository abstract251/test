# 前端当前完成情况与后续改进方向

最后更新：`2026-04-16`

## 1. 文档目的

本文档用于同步当前前端已完成的改造结果、尚未完成的联调项，以及下一阶段建议优先推进的工作。当前内容已按后端最新的 JWT + Spring Security 鉴权方案更新，不再沿用旧的 Cookie 登录说明。

## 2. 当前总体状态

截至 `2026-04-16`，前端已完成从旧 Cookie 方案向 JWT + Spring Security 的核心适配，已覆盖认证、会话恢复、路由权限、控制台菜单、登录页、学生在线考试会话等主链路代码改造，并完成构建验证。

当前可确认的状态如下：

- 登录链路已切换到 `/auth/login`、`/auth/refresh`、`/auth/logout`、`/auth/me`。
- 前端请求层已统一使用 `Authorization: Bearer <token>`，不再依赖 `withCredentials` 和 Cookie。
- 会话存储已改为 `sessionStorage`，由 `src/utils/auth.js` 统一管理。
- 路由角色模型已统一切换为后端角色枚举：`ADMIN`、`TEACHER`、`STUDENT`。
- 学生正式考试流程已切到 `/attempt/start`、`/attempt/answers`、`/attempt/submit`。
- 控制台与学生端的主要业务页面已按新会话模型接入。
- 当前 `npm run build` 已通过，前端构建体积告警也已收敛处理。

## 3. 已完成内容

### 3.1 认证与会话层

已完成：

- 登录页改为提交 `username`、`password`、`role`。
- 登录成功后保存 `accessToken`、`refreshToken`、`expiresIn`、`user`。
- 启动时若本地存在会话，则优先调用 `/auth/me` 恢复当前身份。
- 学生身份恢复后，额外调用 `/student/{id}` 补齐年级、专业、学院等资料。
- Axios 请求拦截器自动注入 Bearer Token。
- 业务请求返回 `401` 时，自动触发一次 `/auth/refresh` 并重放原请求。
- 刷新失败时，清空本地会话并跳回登录页。
- 登出统一调用 `/auth/logout`，无论接口是否成功，本地会话都会清空。

当前结果：

- 刷新页面后，已登录用户可通过 `/auth/me` 自动恢复会话。
- 学生侧依赖资料筛选的页面，不再在资料未就绪时直接误加载。
- 前端内部仍保留旧 `role: '0' | '1' | '2'` 的兼容字段，但权限控制已不再依赖它。

### 3.2 路由权限与页面基础设施

已完成：

- 路由 `meta.roles` 全量切换为 `ADMIN`、`TEACHER`、`STUDENT`。
- 路由守卫基于当前 JWT 会话做登录校验与越权跳转。
- 登录页在已登录状态下会按角色重定向到正确首页。
- 控制台菜单与头部角色展示按 `authRole` 渲染。
- 管理员与教师共享控制台壳层，但菜单权限已按角色区分。
- 教师控制台暂时隐藏自助改密入口，仅管理员保留。

当前结果：

- 学生不能进入控制台路由。
- 教师和管理员访问越权菜单时会被拦回各自首页。
- 页面顶部用户展示、首页跳转、菜单高亮逻辑已与新鉴权模型对齐。

### 3.3 学生在线考试会话适配

已完成：

- 学生考试详情页已改为说明“进入答题页将开始或恢复作答”。
- 答题页统一以 `/student/exam/{examCode}/attempt/start` 作为进入接口。
- 已支持读取后端返回的历史答案并恢复页面状态。
- 答题过程中会调用 `/attempt/answers` 做暂存。
- 页面已增加暂存状态展示，包括保存中、已暂存、暂存失败、最近保存时间。
- 在 `visibilitychange`、`pagehide`、路由离开前做 best-effort 保存。
- 正式交卷统一走 `/student/exam/{examCode}/attempt/submit`。

当前结果：

- 学生刷新页面后，可以按后端 attempt 记录恢复未提交的作答状态。
- 学生进入答题页时，前端不会再自行假设是否新开考，统一以后端返回为准。
- 若学生资料未恢复完成，考试中心会先阻止加载，避免筛选条件失真。

### 3.4 既有业务页面的兼容调整

已完成：

- 登录页完成新接口与角色选择适配。
- 管理员、教师、学生的首页与控制台结构继续保留。
- 学生成绩、学生资料、考试中心、考试详情、答题页等页面已改为从新会话模型读取用户信息。
- 控制台壳层、头部菜单、公共权限工具已切换到新角色常量。

当前结果：

- 现有业务页面仍可复用原有主体结构，不需要推翻重写。
- 主要变更集中在会话来源、权限判断和考试流程对接方式。

### 3.5 构建与打包优化

已完成：

- 移除了 `main.js` 中对 `Element Plus` 的整库注册和整库样式引入。
- 新增 `src/plugins/element-plus.js`，仅注册当前项目实际使用的组件与 `v-loading` 指令。
- 构建配置增加基础的 vendor 分包策略，拆分 `vue/vue-router`、`element-plus`、`axios/dayjs`。
- 关闭生产环境 source map，减少产物体积。
- 调整性能阈值，使构建告警与当前项目实际体量相匹配。

当前结果：

- 构建产物不再因默认的过低阈值持续报体积告警。
- 在不改动现有页面功能的前提下，首屏依赖结构比整库引入更合理。

## 4. 当前未完成项

### 4.1 真实联调与手工回归

当前仍建议在真实前后端联调环境中补完以下验证：

1. 管理员、教师、学生三类账号的完整登录、刷新、退出链路。
2. 学生刷新后恢复会话，再进入考试中心与答题页的真实数据表现。
3. 学生暂存、刷新恢复、继续作答、正式交卷的完整闭环。
4. 越权访问控制台路由、学生路由时的跳转结果是否符合预期。
5. 管理员与教师菜单差异是否和后端授权边界一致。

### 4.2 遗留一致性问题

仍可继续收口的点包括：

- 个别旧页面仍保留历史编码问题，存在乱码风险，建议统一按 UTF-8 再做一轮校正。
- 少量页面仍保留对旧兼容字段的读取，虽然不影响使用，但后续可以逐步清理到仅保留 `authRole`。
- 学生消息中心展示名称逻辑还可以继续统一到 `displayName` 优先。

## 5. 建议的联调顺序

建议按以下顺序做浏览器联调：

1. 先验证 `/auth/login -> /auth/me -> /auth/logout` 的完整闭环。
2. 分别使用管理员、教师、学生账号确认首页跳转和菜单权限。
3. 使用学生账号验证考试中心列表、考试详情页和答题页的进入条件。
4. 在答题页验证自动暂存、刷新恢复、继续作答和交卷。
5. 最后回归成绩页、资料页、消息页等依赖当前会话身份的页面。

## 6. 后续改进方向

高优先级：

- 完成真实浏览器联调，并把结果回填到联调文档。
- 清理旧页面中的乱码与历史编码问题。
- 继续清理残留的旧角色兼容字段，收口到统一的 JWT 会话模型。

中优先级：

- 继续优化学生答题页体验，例如未答题提示、题号导航、强制交卷边界处理。
- 优化消息中心的展示与筛选体验。
- 结合真实监控数据再评估是否需要更激进的拆包策略。

低优先级：

- 进一步压缩前端体积，例如继续减少同步依赖和公共样式体量。
- 对控制台和学生端做更细的视觉统一与移动端收口。

## 7. 结论

当前前端已经完成“新鉴权方案接入”和“学生在线考试会话适配”的主要代码改造，后续重点应从“功能接通”转向“真实联调、收口一致性、继续优化体验”。
