# 当前后端已实现功能说明

## 1. 文档目的

本文档用于说明当前 `backend` 仓库已经落地的后端能力，给开发、测试和前端联调用作统一参考。

对比基线为原项目 `D:\OnlineExam\源代码\OnlineExamSystem\OnlineExamSystemApi - idea`。

## 2. 总体结论

当前后端已经覆盖原项目的大部分核心业务能力，并在考试过程控制、题库聚合、题库删除、成绩统计、考试撤销、快照冻结等方面做了明显增强。

从“业务能力是否具备”的角度看，当前仓库已经可以支撑：

- 登录与登出
- 管理员、教师、学生信息管理
- 三类题目维护：选择题、填空题、判断题
- 试卷题目管理与按科目练习
- 自动组卷
- 考试管理
- 在线考试开考、暂存答案、交卷
- 成绩查询与成绩统计
- 留言与回复
- 全局题库聚合分页与题库删除

从“是否完全兼容原项目旧接口”的角度看，不是 100% 完全兼容，主要差异如下：

- 原 `/answers/...` 题库查询接口已重构，不再作为当前主入口。
- 学生分页和教师分页接口改成了更细的条件过滤路由。
- `GET /paper/{paperId}` 现在增加了学生角色限制，防止考前直接预览整张试卷。
- 新增了学生考试会话流，前端应优先对接新的考试流程接口，而不是只用旧式直接算分接口。

## 3. 基础约定

### 3.1 统一返回结构

绝大多数接口都返回统一结构：

```json
{
  "code": 200,
  "message": "请求成功",
  "data": {}
}
```

说明：

- `code = 200` 表示成功
- 业务异常通常返回 `400`、`401`、`403`、`404`、`410` 等
- `data` 的具体结构由各接口决定

### 3.2 登录态与角色

登录成功后，后端会通过 Cookie 写入：

- `rb_token`: 当前登录账号主键
- `rb_role`: 角色标识

角色值约定：

- `0`: 管理员
- `1`: 教师
- `2`: 学生

### 3.3 时间约定

考试相关时间主要使用上海时区：`Asia/Shanghai`。

`ExamManage.examStartAt` 推荐前端使用 ISO-8601 传入，例如：

```txt
2026-04-22T09:00:00
```

后端同时兼容 `examDate` 的字符串形式，例如：

```txt
yyyy-MM-dd HH:mm:ss
```

## 4. 已实现功能清单

### 4.1 登录与会话

已实现：

- 用户登录 `POST /login`
- 用户登出 `POST /logout`
- 按管理员、教师、学生三类账号识别登录身份
- 登录成功后下发角色 Cookie

### 4.2 管理员管理

已实现：

- 查询全部管理员
- 按 ID 查询管理员
- 新增管理员
- 修改管理员
- 删除管理员
- 重置管理员密码

### 4.3 教师管理

已实现：

- 教师分页查询
- 按多条件过滤：教师编号、姓名、学院、职称/类型、电话、邮箱
- 按 ID 查询教师
- 新增教师
- 修改教师
- 删除教师

### 4.4 学生管理

已实现：

- 学生分页查询
- 按多条件过滤：学号、姓名、年级、电话、学院、专业、班级
- 按 ID 查询学生
- 新增学生
- 修改学生
- 修改学生密码
- 删除学生

### 4.5 题目管理

已实现三类题目的维护能力：

- 选择题新增、编辑、查询最新题号
- 填空题新增、编辑、查询最新题号
- 判断题新增、编辑、查询最新题号

题型编号约定：

- `1`: 选择题
- `2`: 填空题
- `3`: 判断题

### 4.6 全局题库聚合

已实现：

- 全局题库聚合分页接口 `GET /question-bank/{page}/{size}`
- 按题型过滤
- 按科目过滤
- 按关键字搜索题干

实现方式：

- 底层通过 `UNION ALL` 聚合 `multi_question`、`fill_question`、`judge_question` 三张题表
- 返回统一的 `QuestionBankItemVO` 结构
- 方便前端在一个列表里展示完整题库，而不是分别请求三类题目表

### 4.7 题库删除

已实现：

- 删除题库题目 `DELETE /question-bank/{questionType}/{questionId}`

删除规则：

- 先检查题目是否存在
- 再检查该题是否被试卷引用
- 如果引用它的试卷已经进入冻结窗口，或考试已撤销，则拒绝删除
- 如果允许删除，先删除 `paper_manage` 中的关联，再删除对应题目表中的题目记录

### 4.8 试卷管理

已实现：

- 查询全部试卷题目关联 `GET /papers`
- 根据试卷 ID 获取试卷完整题目 `GET /paper/{paperId}`
- 根据科目获取练习题库 `GET /practice/{source}`
- 手动向试卷中加入题目 `POST /paperManage`
- 删除试卷中的某一道题 `GET /paper/delete/{paperId}/{type}/{questionId}`
- 清空整张试卷的题目关联 `DELETE /paper/deleteAll/{paperId}`
- 获取试卷总分 `GET /paper/score/{paperId}`

额外规则：

- 试卷总分由题目数量自动计算，当前实现为每题固定 2 分
- 如果试卷已关联到进入冻结窗口的考试，则不允许继续调整题目结构
- 学生角色不能直接访问 `GET /paper/{paperId}` 查看完整试卷内容

### 4.9 自动组卷

已实现：

- 自动组卷接口 `POST /item`

能力说明：

- 先按 `paperId` 清空旧题目关联
- 再根据科目、选择题数量、填空题数量、判断题数量，从题库中随机/批量抽题入卷
- 如果某一题型数量不足，会直接返回失败

### 4.10 考试管理

已实现：

- 查询全部考试
- 考试分页查询
- 按考试编号查询考试
- 新增考试
- 修改考试
- 删除考试
- 获取最后一条考试记录/最近试卷信息 `GET /examManagePaperId`
- 查询考试策略 `GET /exam/{examCode}/exam-policy`

考试策略接口会返回：

- `examCode`
- `examStartAt`
- `freezeAt`
- `paperLocked`
- `revoked`
- `snapshotReady`
- `windowEndAt`
- `inExamWindow`
- `serverTime`

### 4.11 冻结与锁卷规则

已实现：

- 冻结时刻 = 开考前 1 小时
- 一旦进入冻结窗口，试卷结构视为锁定
- 锁定后不允许再调整试卷题目、删除关联题目、替换试卷、改考试范围等关键结构信息
- 锁定后考试编辑只允许有限字段调整，例如说明、考生提示、考试时长，并且考试时长只能延长不能缩短

### 4.12 考试快照

已实现：

- 冻结试卷快照接口 `GET /exam/{examCode}/frozen-paper`
- 后端会在需要时物化共享快照，确保考试用题在冻结后固定

能力说明：

- 教师/管理员可以查询冻结后的正式试卷内容
- 学生不允许通过该接口在考前预览试题
- 如果尚未到达冻结时点，则快照不会生成，也不能读取
- 考试撤销后，快照接口会拒绝访问

### 4.13 考试撤销

已实现：

- 管理员撤销考试 `POST /admin/exam/{examCode}/revoke`

规则：

- 仅超级管理员可执行
- 必须填写撤销原因
- 撤销后会记录审计信息
- 已撤销考试将不能再参与正常试卷编辑与考试流程

### 4.14 学生在线考试流程

已实现完整学生考试会话流：

- 开始或恢复考试 `POST /student/exam/{examCode}/attempt/start`
- 暂存答案 `PUT /student/exam/{examCode}/attempt/answers`
- 正式交卷 `POST /student/exam/{examCode}/attempt/submit`

流程能力：

- 自动校验学生是否属于本场考试的年级、专业、学院范围
- 自动校验当前时间是否在考试开放窗口内
- 开始考试时返回脱敏后的试卷内容，隐藏标准答案与解析
- 允许重复进入未提交的考试并恢复答案
- 暂存答案时按 `questionType_questionId` 键保存
- 交卷时按冻结后的试卷快照判分，避免考中改题导致判分不一致

### 4.15 直接交卷接口

已实现：

- 直接交卷接口 `POST /answer/submit`

说明：

- 该接口接收 `AnswerVO`
- 会计算得分并写入 `score` 表
- 适合兼容旧流程或简单联调
- 对于正式前端考试流程，优先建议使用新的学生考试会话接口

### 4.16 成绩管理

已实现：

- 查询全部成绩 `GET /scores`
- 分页查询某学生成绩 `GET /score/{page}/{size}/{studentId}`
- 查询某学生全部成绩 `GET /score/{studentId}`
- 新增成绩 `POST /score`
- 查询某场考试全部成绩 `GET /scores/{examCode}`

### 4.17 成绩统计

已实现：

- 成绩统计接口 `GET /score/statistics/{examCode}`

返回能力包括：

- 平均分 `avgScore`
- 最高分 `maxScore`
- 最低分 `minScore`
- 及格率 `passRate`
- 参考人数 `totalCount`
- 分数段分布 `distribution`

分数段默认划分为：

- `0-59`
- `60-69`
- `70-79`
- `80-89`
- `90-100`

### 4.18 消息交流

已实现：

- 留言分页查询 `GET /messages/{page}/{size}`
- 留言详情 `GET /message/{id}`
- 新增留言 `POST /message`
- 删除留言 `DELETE /message/{id}`
- 新增回复 `POST /replay`
- 按留言查询回复列表 `GET /replay/{messageId}`

## 6. 前端对接建议

建议前端按以下优先级对接：

1. 登录后保存并自动携带 Cookie，尤其是 `rb_token` 和 `rb_role`
2. 题库列表统一走 `GET /question-bank/{page}/{size}`
3. 正式考试流程优先走学生考试会话接口，而不是旧式直接交卷接口
4. 教师端/管理员端如果需要查看正式考试题目，优先走冻结快照接口
5. 删除题目、编辑试卷、修改考试前，应处理后端关于“冻结/撤销”的业务拒绝提示
6. 学生和教师分页查询若不需要某个筛选项，请使用 `@` 作为空占位

## 7. 需要注意的兼容差异

这些差异不会影响当前后端能力完整性，但会影响旧前端直接复用：

- 原 `/answers/{page}/{size}/{subject}/{section}/{question}` 不再是当前主入口
- 原 `/answers/{type}/{questionId}` 单题查询能力已拆分为题库聚合接口和三类题目独立接口
- 学生分页接口新增 `studentId` 过滤位
- 教师分页接口新增多条件过滤参数
- 部分历史接口仍沿用旧风格，例如单题删除关联使用 `GET /paper/delete/...`
